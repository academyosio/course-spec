# v0.1.0

**Release Date:** 2026-10-27

The first release of **course-spec**: an open format for keeping a complete
online course in one directory under version control, with Go types, a
loader, generated JSON Schemas, and the `coursespec` command that checks a
course and reports what changed since it was published.

## Highlights

- **One directory per course:** `course.json`, a `section.json` per section,
  HTML decks with narration, translations, pronunciations, quizzes with answer
  keys, and published state, all JSON with camelCase properties
- **Lessons discovered from decks:** a slide with `data-lesson` starts a
  lesson and its `data-id` is the lesson's stable ID, in videoascode's deck
  conventions
- **`coursespec validate`:** every problem with its file, location, code, and
  fix, as text or JSON, for one course or every course beneath a directory
- **Content fingerprints:** each lesson's slides and narration in every
  language hashed, so `coursespec lessons` reports what changed since it was
  published, even in a fresh clone
- **Quizzes in the course:** multiple-choice, true/false, and short-answer
  questions with explanations, checked for answer patterns a learner could
  pass by

## Added

- Go types for the course and section manifests, lessons, quizzes,
  pronunciations, and published state, with strict decoding that rejects
  unknown properties
- `coursespec.Load`, which resolves a course directory into one value:
  sections, lessons discovered from decks with manifest details applied,
  translations matched to slides, quizzes, pronunciations, and published state
- `coursespec.Find`, listing every course beneath a directory
- Planned sections (`"released": false`) that a course can list before their
  files exist
- Quiz-only sections for final assessments
- Text lessons placed among deck lessons with `after`, and retired lessons that
  keep a published ID
- The `deck` package: slides, lessons, narration with `[PAUSE:ms]` directives,
  the files a deck loads, transcript matching by slide ID or position, and
  content fingerprints
- The `validate` package: schema, ID, section, deck, transcript, quiz,
  change-log, and published-state checks, with warnings for unnarrated slides,
  long lessons, remote deck files, missing translations, answer patterns, and
  unversioned changes
- Publish status for each lesson and quiz: `new`, `changed`, `published`,
  `retired`, or `planned`
- `coursespec.WritePublished` and a platform `revision` in published state
- Generated, embedded, and linted JSON Schemas for `course.json`,
  `section.json`, `quiz.json`, and `published.json`
- The `coursespec` command: `validate`, `lessons`, and `schema`, with
  `--format json`
- A documentation site with guides for the format, validation, AI agents, and
  the Go library

## Format decisions in this release

- Every `sections` entry is an object with a `path`, so the schema has no
  union type
- The pronunciation file is `pronunciations.json`
- A deck loads only local files; remote files are reported
- Renaming a slide isn't a content change, so a renamed lesson keeps its
  fingerprint and the validator can name the likely rename

## Installation

```bash
go install github.com/academyosio/course-spec/cmd/coursespec@v0.1.0
go get github.com/academyosio/course-spec@v0.1.0
```
